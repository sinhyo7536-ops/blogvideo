## 1. 지금 프로그램 분석

### 1.1 구조와 기술

| 구분 | 내용 |
|---|---|
| 형태 | 윈도우 데스크톱 앱. FastAPI 로컬 서버(127.0.0.1:8765) + Chrome(없으면 Edge) 앱 창 |
| 언어·라이브러리 | Python 3.12, FastAPI, Pydantic, httpx, BeautifulSoup, Pillow, anthropic, google-genai, edge-tts, yt-dlp |
| 영상 | FFmpeg(번들 포함). 장면 조각 → xfade 전환으로 잇기 → 목소리·배경음악 |
| 화면 | 빌드 도구 없는 HTML/CSS/JS 한 장(`app/web/`) |
| 배포 | PyInstaller + Inno Setup. 키 포함 지인용 설치 파일은 앱 설정 화면에서 로컬로만 생성(DPAPI) |
| 코드 규모 | 앱 약 4,600줄(파이썬 23개 파일 + 화면 3개), 테스트 27개 파일 316개 |

```
app/
  launcher.py   실행 진입점 (키 가져오기 → 인증서 → 서버 → 앱 창 → 창 닫힘 감시)
  main.py       API 라우트, 이 PC 전용 미들웨어
  jobs.py       작업 큐(워커 1개), 단계 상태 저장(state.json), 멈추기
  models.py     BlogPost, Scene, VideoScript, RenderOptions, JobState
  scraper/naver.py  네이버 글·사진 추출, 원본 사진 받기
  script.py     Claude 대본 + ask_claude(공통 호출)
  gemini.py     제미나이 대본 + ask_gemini(공통 호출)
  director.py   연출 요청 → 장면 설정 (0.6.0, 미커밋)
  tts.py        Edge TTS 13개 목소리·속도, 4개씩 동시 생성
  captions.py / visuals.py  자막·제목 띠·장소 이름표·시작/끝 화면·썸네일, 스타일 3종
  render.py     영상 합성, 8장면씩 묶어 잇기(길이 제한 없음), 색감·세기·머무름
  ytmusic.py    유튜브 링크 → 배경음악 MP3
  config.py / secret.py / keybundle.py  설정, 키 암호화, 키 포함 설치 파일
```

### 1.2 지금의 작업 흐름

```
주소 입력 + AI 선택(클로드/제미나이) → [글·사진 수집 → AI 대본] → 대본 고치기 화면
→ 영상 만들기 → [연출 요청 반영 → 목소리 → 영상] → 결과(MP4·썸네일·제목/설명/태그 복사)
```
"AI 없이 직접 작성하기"(작은 버튼)로 글·사진만 불러와 장면을 직접 만들 수도 있다.

### 1.4 알려진 문제·미완성

- 커밋하지 않은 0.6.0 변경이 있다(장면별 "연출 요청" 칸). 사용자가 이후 "장면마다 다 요청하기보다 Vrew처럼"이라고 해서 방향이 바뀌었다.
- 작업 폴더가 7일 뒤 자동으로 지워진다 → "프로젝트를 다시 열어 이어 하기"와 충돌.
- 사진을 못 받아도 알리지 않는다 → "임의로 만들지 말고 알려줄 것" 원칙과 충돌.
- 실제 여행 글로는 아직 시험하지 않았다(네이버 공식블로그 글로만 확인).
- 제미나이는 대본을 원문의 절반쯤으로 줄인다(실제 호출 확인).

## 2. 큰 구조 변경 두 가지 (먼저 설명하고 승인받을 것)

### 2.1 "작업(Job)" → "프로젝트(Project)"
- **이유**: 여러 게시글 URL을 한 여행으로 묶고, 프로그램을 껐다 켜도 여행별로 이어 하려면 "URL 1개 = 작업 1개" 구조로는 안 된다.
- **방법**: 기존 `JobManager`(큐·단계·멈추기)는 그대로 두고, 그 위에 프로젝트 층을 얹는다.
  - 프로젝트 폴더: `%LOCALAPPDATA%\BlogVideo\projects\<id>\` 에 `project.json`, `posts/`(게시글별 원문·사진), `analysis.json`, `script.json`(버전 기록 포함), `audio/`, `render/`
  - `BlogPost` 여러 개 → 통합 자료 → 대본 1개 → 영상
- **영향**: 처음 화면이 "프로젝트 목록 + 새 프로젝트"로 바뀐다. 자동 삭제는 프로젝트에는 적용하지 않는다(용량 표시와 직접 삭제 버튼 제공). 예전 작업(jobs 폴더)은 첫 실행 때 프로젝트로 옮긴다.

### 2.2 대본 생성을 "분석 → 대본" 두 번의 AI 호출로 나누기
- **이유**: "사실과 추론 구분", "날짜별 일정", "식당 ↔ 사진 연결"을 확인 가능한 형태로 남기려면, 대본을 쓰기 전에 분석 결과를 따로 만들어 저장해야 한다. 분석 결과는 화면에서 보여 주고, 대본·사진 매칭·쇼츠·검수가 모두 이것을 다시 쓴다.
- **영향**: AI 호출이 한 번 늘어난다(분석은 게시글마다 1회, 결과를 저장해 다시 쓰므로 재생성 때는 대본만 호출).

## 3. Claude 모델 운영안 (2단계)

모델 ID는 코드에 쓰지 않고 `config.json` 의 `models` 항목과 설정 화면에서 바꾼다. 기본값은 아래처럼 제안한다.
가격은 2026-11 기준 Anthropic 공식 요금(100만 토큰당 입력/출력).

| 작업 | 제안 기본 모델 | 이유 |
|---|---|---|
| 여행 대본 생성, 전체 재생성, 쇼츠 대본 | Claude Opus 5.5 (`claude-opus-5-5`, $4/$20) | 결과물의 핵심. 지금도 이 모델(사용자 선택) |
| 여행 분석(게시글·사진 읽기) | Claude Sonnet 5.5 (`claude-sonnet-5-5`, $2/$10) | 사진이 많아 입력이 크다. 정리·분류 위주 |
| 사진 분류·관련도 점수·매칭 | Claude Sonnet 5.5 | 사진 판단이 필요, 양이 많음 |
| 문단 AI 재작성·말투 변경·길이 조절 | Claude Sonnet 5.5 | 짧고 자주 부름 |
| 맞춤법·문맥 검토, 영상 검수 | Claude Haiku 5.5 (`claude-haiku-5-5`, $0.10/$0.50) | 단순 확인, 매우 저렴 |
| 유튜브 제목·설명·태그·썸네일 문구 | Claude Haiku 5.5 | 짧은 글 |

- 모든 작업에서 같은 시스템 프롬프트·자료는 프롬프트 캐싱으로 다시 쓴다(같은 프로젝트에서 재작성·재생성이 반복되므로).
- 결정: 위 배분을 기본값으로 쓴다.
- 결정: 제미나이는 뺀다(2단계).

## 4. 단계별 계획

| 단계 | 내용 | 주요 파일 | 확인 방법 |
|---|---|---|---|
| 1 | 분석·계획 (이 문서) | `docs/고도화계획.md` | 사용자 검토 |

| 3 | 프로젝트 구조, 여러 URL, 작성 날짜, 중복 글·중복 사진 제거(사진 지문), 수집 실패 목록과 재시도, 사진 직접 올리기 | `app/projects.py`(신규), `scraper/naver.py`, `models.py`, 화면 | 실제 네이버 글 2~3편(중복 포함)으로 수집, 껐다 켜서 이어 하기 |
| 4 ✅ | AI 여행 분석(사실/추론 구분, 일정, 장소, 사진별 특징), 대본 스타일 5종과 대본 설정(길이·분량·말투·비중·상세도), 작성 날짜·받지 못한 사진 알림·중복 사진 제거 (2026-11-15 완료) | `app/ai/analyze.py`, `app/ai/writer.py`(신규) | 실제 여행 글로 분석·대본 생성, 원문에 없는 내용이 섞이는지 점검 |
| 5 | 대본 편집기: 전체 보기, 문단 수정·추가·삭제·이동, 문단 AI 재작성 명령, 말투·길이 조절, 맞춤법 검토, 전후 비교, 자동 저장, 버전 기록, **대본 확정** | `app/ai/rewrite.py`(신규), 편집 화면 | 브라우저 자동 테스트 + 실제 재작성 호출로 "다른 문단은 그대로"인지 확인 |
| 6 | 사진 분류·관련도 점수, 문장 ↔ 사진 자동 매칭, 추천 사진 다시 고르기, 사진 제외, 장면당 여러 사진, 사진별 표시 시간 | `app/ai/photos.py`(신규), `render.py` | 실제 여행 사진으로 매칭 결과 확인 |
| 7 | 영상 프리셋 4종, 1:1 출력, 바뀐 장면만 다시 만들기(목소리·장면 조각 재사용), 여러 사진 장면 렌더링 | `render.py`, `tts.py`, `jobs.py` | 한 문단만 고친 뒤 다시 만들 때 걸린 시간과 결과 비교 |
| 8 | 쇼츠 자동 제작, AI 영상 검수(오탈자·싱크·반복 사진·노출 시간), 유튜브 문구 확장 | `app/ai/shorts.py`, `app/ai/review.py`(신규) | 실제 영상으로 쇼츠·검수 보고서 생성 |
| 9 | 전체 통합 테스트, 설치 파일, 지인 PC 시나리오 | 전체 | 새 설치 → 키 포함 설치 파일 → 실제 여행 글 2편으로 끝까지 |

**진행 순서(결정 반영)**: 2 → 4 → 5 → 6 → 7 → 3(프로젝트·여러 URL) → 8 → 9.
3단계 중 프로젝트와 무관한 것(작성 날짜, 수집 못 한 사진 알림, 중복 사진 제거)은 4단계에 함께 넣는다.

각 단계 끝에 보고: 구현 기능, 수정·신규 파일, 테스트 결과(자동 + 실제 실행), 발견한 오류, 남은 작업, 다음 단계 계획.

## 5. 지킬 원칙
- 지금 되는 기능(영상 엔진, 스타일, 목소리, 배경음악, 멈추기, 키 포함 설치 파일)은 지우지 않고 확장한다.
- 새 AI 기능은 `app/ai/` 아래 모듈로 분리하고, 기존 `script.py`·`gemini.py` 호출부는 유지한다.
- 블로그에 없는 경험·사실을 만들지 않는다. 분석 결과에 "확인된 사실 / AI 추론"을 구분해 저장하고 화면에 표시한다.
- 수집 실패·사진 누락은 사용자에게 목록으로 알린다.
- 실제 실행 테스트 없이 완료라고 보고하지 않는다. AI 실제 호출은 비용이 들므로 단계마다 1~2회로 제한한다.
